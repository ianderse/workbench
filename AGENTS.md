# Working agreements

Read `PROGRESS.md` for current status/navigation and `CLAUDE.md` for standing rules. Follow task-relevant canonical links; do not routinely load the entire docs folder or historical logs. Detailed architecture remains available in `docs/workbench-reference.md`. Progress is not approval, acceptance, or a substitute for required checks.

## Git delivery

- Commit completed, validated work in this repository before reporting it done. Do not wait for a separate request to commit, unless the user explicitly asks to leave changes uncommitted.
- Inspect the working tree first, preserve existing work and honor the user's requested commit scope.
- Verify the working tree after committing and report any changes that remain. When pushing, verify the remote branch contains the delivered commit.
